** Coding Standards

*** Code Style

**** Zig Naming Conventions
- =camelCase= for functions and methods
- =PascalCase= for types, structs, enums, unions
- =snake_case= for local variables, parameters, and struct fields
- =SCREAMING_SNAKE_CASE= for compile-time constants
- Prefix unused variables with =_=

**** Zig Idioms
- Explicit is better than implicit — no hidden control flow or allocations
- Prefer =comptime= for compile-time known values and zero-cost abstractions
- Use slices (=[]T=) over pointers-to-arrays when size is runtime-known
- Prefer tagged unions over boolean flags for state machines
- Use =std.meta= and =@typeInfo= for generic programming when appropriate
- Use sentinel-terminated slices (=[:0]const u8=) for C interop

**** Memory Management
- *All allocations through =std.mem.Allocator= parameter* — never use a global allocator
- Document which functions allocate and caller's responsibility to free
- Use =defer= for deterministic cleanup
- Use =errdefer= for cleanup on error paths
- Prefer arena allocators for request-scoped or batch operations
- Use =std.testing.allocator= in tests to detect memory leaks
- Consider fixed-buffer allocators for bounded operations

**** Error Handling
- Use error unions (=!T=) for all fallible operations
- Define specific error sets per module — avoid =anyerror=
- Use =try= for propagation, =catch= for recovery
- Use =errdefer= for cleanup on error paths
- Return errors to callers — don't silently swallow failures
- Provide error context through structured error types or logging

**** Code Organization
- Keep public API surface minimal — default to private, use =pub= judiciously
- Group related types and functions in the same file
- One concept per file — avoid monolithic source files
- Export module API through a root file that re-exports public symbols
- Co-locate tests with the code they test (inline =test= blocks)

*** File I/O Patterns (Zig 0.16+)
- Use =std.Io.Dir= and =std.Io.File= for all file operations — all take =io= parameter
- =file.writePositionalAll(io, bytes, offset)= / =file.readPositionalAll(io, buf, offset)= for positional I/O
- =dir.createFile(io, name, .{ .read = true, .truncate = false })= for creating files
- =dir.openFile(io, name, .{ .mode = .read_write })= for opening existing files
- =file.stat(io)= for metadata, =file.sync(io)= for fsync, =file.close(io)= for cleanup
- Use =defer file.close(io)= immediately after opening
- For raw syscalls (flock, temp files): =std.os.linux.open=, =.close=, =.write=, =.read=, =.flock=, =.unlink=

*** Networking Patterns (Zig 0.16+)
- Use =std.Io.net.IpAddress.listen(io, .{})= for server binding
- Use =std.Io.net.IpAddress.connect(io, .{ .mode = .stream })= for client connections
- Extract =.socket.handle= from =net.Stream= for raw posix fd operations
- Protocol read/write uses raw posix fd (=std.posix.read= / =std.os.linux.write=) — not Io.Reader/Writer
- Thread-per-connection model (=std.Thread.spawn=, =thread.detach()=)
- Track active connections with =std.atomic.Value(u32)= for =max_connections= enforcement

*** Serialization
- =std.json.Stringify.valueAlloc(allocator, value, .{})= for encoding structs to JSON
- =std.json.parseFromSlice(T, allocator, body, .{ .allocate = .alloc_always, .ignore_unknown_fields = true })= for decoding
- Binary wire format: manual =std.mem.writeInt= / =std.mem.readInt= with =.little= endianness
- *Emit a frame in one syscall.* A header written separately from its body is correct on the wire and costs about 41 ms per response: the header goes out, Nagle holds the body because there is unacknowledged data and the body is a small partial segment, and the peer's delayed ACK fires at 40 ms on Linux. Use =writev= with one iovec per part — one syscall, no copy, no allocation, and the frame becomes indivisible by construction. Do not reach for =TCP_NODELAY=: it masks the symptom, keeps the extra syscall, and turns the next split message into a silent cost instead of a visible one. This applies to any header-plus-payload protocol, not only this one.
- *Resume a partial =writev= by advancing, never by restarting a buffer.* The remainder can begin part-way through the header, exactly at the boundary, or part-way through the body. Restarting either puts duplicate bytes on the wire and desynchronises the peer's framing for the life of the connection — a corrupted stream, not a slow one. Test the arithmetic directly; a socket will not produce a short write on demand, and "we never saw one" is not evidence.
- *When a latency number looks like a cost you already know about, check the minimum before believing it.* "Publish round-trip: median 41.59 ms, min 1.27" was written off as fsync for most of a task. Disk cost does not vanish on one call in twenty — the minimum said the median was a timer, and it was the delayed ACK above. A tight distribution around 40 ms, 200 ms or 1 s is a protocol or scheduler artefact until proven otherwise.
- Validate all untrusted input — check message sizes, offset bounds, topic name characters
- *Any enum decoded from bytes you did not write must be non-exhaustive* (=_,=). =@enumFromInt= on an exhaustive enum is illegal behaviour for every unassigned value: in Debug and ReleaseSafe that is a panic, and a panic on a connection thread ends the whole process, so one byte from any peer that can reach the port is a remote kill. Non-exhaustive makes the decode total and pushes the decision "what is this?" out to the dispatch, where an unknown value can be answered with an error instead of being fatal. This bit the wire protocol (=v0.1/protocol-unknown-opcode.org=); it applies to any tag byte, kind field, or schedule type that ever arrives from a socket or a file.
- *A typed value is not a validated value.* Once =@enumFromInt= has run, the rest of the code sees a =MessageType= and reasonably assumes something checked it. The wire-protocol spec even listed "validate msg_type is a known enum value" as a requirement, and its absence went unnoticed for the life of the protocol, because the type system made the check look already done. When reading a validation checklist against an implementation, confirm each item has a line of code — do not accept a type as evidence.
- Shell-escape all strings passed to fork/exec (single-quote wrapping with ='\''= escape)

*** Process Spawning Patterns
- =std.os.linux.fork()= / =.execve()= / =.waitpid()= for running external commands
- Pass environ from =init.minimal.environ.block= to child =execve= through a small compatibility helper: 0.16.0 exposes =block.slice.ptr= while newer 0.16-dev/0.17 builds may expose =block.ptr=
- For stdin: write to temp file with =O_CREAT|O_EXCL|O_NOFOLLOW=, redirect via shell =<= (current approach; pipe2() preferred, see =stdin-pipe.org=)
- PID-based temp file paths (=/tmp/.ever-hook-stdin-{pid}=) to avoid collisions
- Validate env var keys (alphanumeric + underscore only) before shell interpolation

*** Zig 0.16/0.17 API Notes (Learnings)
- *Io parameter*: All file, directory, and network operations require an =std.Io= parameter. In tests use =std.testing.io=. In =main=, accept =std.process.Init= and use =init.io=.
- *ArrayList is unmanaged*: =std.ArrayList(T)= is now the unmanaged variant. Use =.empty= to initialize, pass allocator per-call: =list.append(allocator, item)=, =list.deinit(allocator)=, =list.toOwnedSlice(allocator)=.
- *Dir operations*: =Dir.openDir=, =Dir.createFile=, =Dir.openFile=, =Dir.iterate= all require =io= parameter. For iteration, the dir must be opened with =.iterate = true=.
- *File I/O*: Use =file.writePositionalAll(io, bytes, offset)= and =file.readPositionalAll(io, buf, offset)=. No =writeAll=/=preadAll= without io.
- *Networking*: =std.net= is gone. Use =std.Io.net.IpAddress=, =.listen(io, opts)=, =.connect(io, opts)=. Server returns =net.Stream= with =.socket.handle= for the posix fd.
- *No =std.posix.write=*: Use =std.os.linux.write= directly with manual errno handling, or use Io.net Stream's writer.
- *No =std.posix.socket=*: Use =std.Io.net.IpAddress.listen()= / =.connect()= instead.
- *JSON*: =std.json.Stringify.valueAlloc(allocator, value, .{})= replaces the old =stringify= with writer pattern.
- *Time*: =std.time.milliTimestamp()= and =std.time.Timer= are gone. Use =std.os.linux.clock_gettime(.REALTIME, &ts)= for wall clock, =.MONOTONIC= for elapsed time. =std.posix.clock_gettime= is also removed in newer builds.
- *Enum from int*: =std.meta.intToEnum= is gone. Use =@enumFromInt(value)= builtin.
- *tmpDir in tests*: Pass =.{ .iterate = true }= if you need to iterate the directory.
- *Main signature*: Use =pub fn main(init: std.process.Init) !void= to get allocator, io, and args.
- *Args iteration*: Use =std.process.Args.Iterator.init(init.minimal.args)= then =.next()=.

- *Mutex and friends live in =std.Io= now, not =std.Thread=, and they did not disappear.* =std.Thread.Mutex= is gone, but =std.Io.Mutex=, =std.Io.Condition=, =std.Io.RwLock=, =std.Io.Semaphore= and =std.Io.Event= all exist in the pinned snapshot, built on =io.futexWait= / =io.futexWake=. *Use them for anything that might wait.* =std.atomic.Mutex= is a *spinlock* (=tryLock= in a =spinLoopHint= loop) and a thread that loses it burns a core until it wins — acceptable only for a lock held for a few instructions, never for one held across syscalls or disk I/O. This entry previously said the blocking primitives were gone; that was wrong, and it is why the store's locks were spinlocks and why a blocking fetch had nothing to wait on and slept in a loop instead. See =v0.1/store-blocking-locks.org=.
- *The =std.Io= sync primitives work from plain =std.Thread.spawn= threads*, not just from =io.async= tasks. On Linux =io.futexWait= is the =futex(2)= syscall and the cancelation check returns early when the calling thread is not an =Io= thread. Verified against =std.testing.io= too, so they are usable in tests. Take the =Uncancelable= variants (=lockUncancelable=, =waitUncancelable=) unless the code genuinely participates in =Io= cancelation — the cancelable ones return =Cancelable!void= and turn every acquisition into an error path.
- *=Io.Condition= is a re-check loop, never a delivery mechanism.* =waitTimeout= returns on signal, on timeout, and spuriously; the predicate must be re-tested after every wake. Signal from inside the critical section that changes the predicate, so a waiter cannot miss the change it is waiting for.
- *StringArrayHashMap*: 0.16.0 only exposes the unmanaged-style =StringArrayHashMapUnmanaged= / =std.array_hash_map.String= API (allocator per call). Some 0.16-dev snapshots exposed a managed =std.StringArrayHashMap=. Prefer compatibility aliases that use unmanaged calls.
- *Unmanaged allocator pattern*: Zig 0.16+ continues moving containers toward allocator-per-call APIs. Pass allocator per-call rather than storing in structs when possible. Handler functions should accept allocator as an explicit parameter.
- *std.debug.print format widths*: Format widths are comptime-only. For runtime-width padding, use manual loops.

*** Event Memory Ownership
- =Log.read()= and =Log.readBatch()= return events with topic+key+value in a single contiguous allocation
- Always use =store.freeEvent(allocator, event)= to free — never free fields separately
- The allocation starts at =event.topic.ptr= and covers topic+key+value contiguously

*** Architectural Learnings
- *Shared log beats per-topic files*: Cross-topic queries go from N file reads to one sequential read. OS page cache works optimally. The rewrite was ~25% of the codebase but simplified server handlers significantly.
- *Topic creation must write to the log*: =createTopic= writes a marker event (empty value) so =rebuildIndex= discovers the topic on restart. Without this, empty topics vanish.
- *fetch must filter markers*: Events with =value.len == 0= are internal markers, not user events. Both =fetch= and =fetchPattern= skip them.
- *Blocking fetch > polling*: Server holds the TCP connection with a sleep loop when =block_ms > 0=. Eliminates client-side polling for =ever on=, =ever sub --follow=, =ever wait=.
- *snapshot() must deep-copy*: =HookTable.list()= returns internal references. If used across mutex boundaries (like building a JSON response), another thread could invalidate them. Always use =snapshot()= for cross-thread access.
- *Shell escaping is security-critical*: Every string interpolated into a shell command (topic names, keys, env vars, cwd) must be single-quote escaped. A topic name containing ='= breaks out of quoting context. Use =appendShellEscaped= helper.
- *JSON escaping needed everywhere*: Topic names, keys, and values all need escaping when building JSON strings manually. Use =appendJsonEscaped= helper.
- *Debug vs ReleaseFast differ*: Data races may only manifest in release builds. Always test =zig build -Doptimize=ReleaseFast= before committing concurrency changes.
- *The visible half of a two-part guarantee is the half that gets implemented.* When an operation must both answer the caller and change state, the answer is the part that every test and every manual check exercises, and the state change is the part that can be missing without anyone noticing. When adding a handler that reports success, write the assertion against the state, not against the reply.

  *This is the most productive defect class this project has.* Every instance below was found by reading or measuring, none by using the system — which is the definition of the shape, because from outside a working one and a broken one are identical:

  | Found      | The visible half                                  | The missing half                                          |
  |------------+---------------------------------------------------+-----------------------------------------------------------|
  | 2026-08-05 | =publish= returns an offset                       | a tombstone-keyed event no read path will ever show        |
  | 2026-08-08 | =ack_ok=                                          | the cursor was never stored                                |
  | 2026-08-08 | an =else= arm reading as the unknown-opcode guard | unreachable; the spec's "validate msg_type" was never written |
  | 2026-08-09 | =readBatch='s "serialise via TopicManager's mutex" | that mutex excludes nothing that appends — segfault         |
  | 2026-08-09 | =publish= reports success with sync on            | =sync(...) catch {}= — a failed fsync is discarded          |

  *How to find the next one, since reading for it works and using the system does not:*
  1. *Grep for discarded results on state-changing calls* — =catch {}=, =_ = f()=, =catch return= — and ask what the caller was told. The =fsync= swallow sits five lines from a =write= failure that is handled correctly, so proximity to good code is no defence.
  2. *Read every comment that asserts a guarantee and find the line that provides it.* Three of the five above were documented and absent: a spec step never written, a doc comment naming a lock that does not apply, a Non-Goal describing protection that did not exist. A comment is a claim, not evidence.
  3. *When a checklist exists, tick it against the code.* =wire-protocol.org= listed three validations; two were implemented; nobody had checked.
  4. *Ask what a test would have to assert to distinguish the two cases.* If the answer is "nothing observable", that is the defect, not a testing gap.
- *Lockfile released on process death*: =flock= is automatically released by the kernel when the process exits (even kill -9). No stale lockfile cleanup needed.
- *reuse_address=false is essential*: With =true=, multiple stores bind to the same port and clients get randomly routed. Set =false= so the OS rejects duplicate binds.
- *Field propagation discipline*: Adding a field to a data struct (Hook, Timer, etc.) requires coordinated updates across 12+ locations: struct definition, JSON serialization struct, legacy struct, add/addFull method, load method, saveLocked, deepCopy helper, free/freeCopy helper, protocol message struct, server handler, client struct+methods, CLI handler. Missing any one causes silent data loss or distant compile errors.
- *Signal handler safety*: Only async-signal-safe operations in signal handlers. To unblock a blocking =accept()= call, use a dummy self-connection (socket+connect+close) — raw syscalls are signal-safe. Never call =deinit()= or manipulate complex structs in a signal handler.
- *Mutex scope for I/O*: Copy index data under the lock, release it, then do disk I/O without the lock. =Log.append= has its own mutex, so =TopicManager= doesn't need to hold its mutex during writes. =fetchPatternByOffset= is the exception and knows it — =readBatch= is not safe against concurrent appends — so it holds the manager lock across a whole scan. That is why the manager lock must block rather than spin: its waiter is a publisher and the wait is as long as the scan.
- *A skip count is not an array index.* Topic offsets index *records*; the topic-local cursor counts *non-marker events*. Translating one to the other by counting markers while reading is both O(topic) and easy to get wrong — it shipped wrong, returning events the caller had asked to skip. Keep the marker positions in the index and translate arithmetically, and keep skipping markers in the read loop anyway so a stale translation degrades to slow rather than to incorrect.

** Repository Traps

Behaviours that cost an implementer real time and are not discoverable by reading the code you are changing. Each was found the expensive way; add to this list rather than rediscovering.

*** Toolchain

- *The pinned Zig snapshot is a pin, not a minimum.* =minimum_zig_version= reads like a floor, so a newer 0.17-dev =zig= on =PATH= satisfies the manifest and then fails to compile the tree, because the development line renames std APIs underneath it. The symptom is a compile error in code you did not touch — e.g. =error: no field named 'params' in struct 'lang.Type.Fn'= from =@typeInfo(...).@"fn".params= against a snapshot where that field moved. Use =nix develop= / =direnv=, or invoke the pinned toolchain directly; do not "fix" the std API drift.

*** Testing

- =zig build test= *prints nothing on success.* Silence means pass — and equally means you ran the wrong step, or everything was cached. Always pass =--summary all=, which gives per-binary counts and distinguishes "ran" from "cached".
- *Tests live in three separate binaries*: =root.zig= (via =refAllDecls=), =main.zig=, and =src/tests/integration.zig=. A test added to a file not reachable from =root.zig= *silently never runs*. You will not see a failure; you will see success. Confirm new tests actually execute.
- *Build a negative control before trusting a new test.* Copy the tree to =/tmp= (=src=, =build.zig=, =build.zig.zon=, =zig-pkg= build standalone), remove the fix, and run the suite. A test that does not fail without the fix is decoration. This is the difference between "the guard works" and "the exploit never ran". Cheaper variant when the fix is not yet applied: write the test first and run it against the untouched tree — same evidence, no copy.
- *A malformed-input test must not construct its input through the API that rejects it.* A test for "the server survives an unknown opcode" written with =writeFrame(fd, @enumFromInt(0x11), ...)= cannot serve as a negative control, because on the un-fixed tree the =@enumFromInt= traps in the *test* process — you learn nothing about the server. Assemble the bad input as raw bytes so the test compiles and runs identically before and after the fix. The same applies to any invalid frame, record, or config the fix teaches the code to reject.
- *The correct server shutdown sequence appears exactly once*, in the first test of =src/tests/integration.zig= — which is named for status probing, so grepping for shutdown-related words will not find it. The order is: set =shutdown_requested=, call =probeServer= to wake the blocked =accept()=, *then* join, *then* =shutdown()=. Do not stand up =Server= and =HttpServer= in one test; that combination deadlocks holding both listeners at 0% CPU. See =air/v0.1/testable-server-lifecycle.org=.

*** Client and CLI

- =ever pub= *never sets a key* — =main.zig= calls =c.publish(topic, null, data)= unconditionally. Anything requiring a keyed publish is not reproducible with the shipped CLI; use the HTTP endpoint (where =key= is a JSON field) or raw frames. Frame layout: byte 0 = version (1), byte 1 = message type, =u32= little-endian body length, then the JSON body.
- =client.Client= *cannot observe a specific server error.* It collapses every =error_response= into =error.ServerError= and prints the message to stderr via =std.debug.print=. Asserting on a particular failure code requires raw frames.

*** Store internals

- =TopicManager.mutex= is *non-reentrant*. Any public method that locks deadlocks if called from inside a locked section — which is why the =*Locked= entry-point variants exist. Validation that needs manager state must either take a =*Locked= path or be pure and run before the lock.
  (Corrected: an earlier version of this entry called it a *spinlock*, transcribed from a worker's learnings report without checking. At =main= both =TopicManager= and =Log= use =std.Io.Mutex=, which parks; only =HookTable= and =ProcessTable= still use =std.atomic.Mutex=. The non-reentrancy is the part that matters and is unchanged. A learnings report is testimony, not evidence — verify before writing it into context as fact.)
- *Empty-valued events are internal markers* and are filtered from every read path. This was documented before it was ever filed as a defect: see the doc comment on =TopicIndex.non_marker_count=, which names user publishes with empty values as a historical quirk. Reading that comment is faster than rediscovering the behaviour.
- *Input guards are not retroactive.* =publish= now rejects reserved keys and empty values, but events already on disk are unchanged and =rebuildIndex= still reads them exactly as before. Guards stop new writes; they do not clean up or reinterpret old ones, and no migration exists.
